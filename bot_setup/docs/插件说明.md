# 佳树机器人 · 设计说明

本文说明机器人现在的结构、各插件的做法和主要配置项。开发过程中的历史、试验和事故记录不在这里，在作者本机的 `docs/开发记录.md`（不进仓库）。

## 总体结构

角色本体和聊天平台分开：心情、记忆、知识、生活、说话方式和感官放在 `kaju_core`，不依赖 AstrBot，也不认识任何聊天软件；QQ、B站、抖音只是接进来的平台，所有平台共用同一个她。

| 层 | 位置 | 作用 |
|---|---|---|
| 角色本体 | `kaju_core/` | `senses`（感官）、`heart`（心情）、`memory`（记忆）、`learn`（学习）、`life`（生活）、`voice`（说话）；`people.py` 身份表、`body.py` 宿主接口、`parts.py` 各部分登记表、`paths.py` 数据位置 |
| 平台 | `kaju_platforms/` | `bili`、`douyin`（链接、登录、私信、下载）、`shared`（自己刷视频、私信规则、找主人）、`dm`（私信逻辑）、`qq`（QQ 上的动作） |
| 宿主适配 | `kaju_astr/` | `body.py` 接口在 AstrBot 上的实现（`AstrBody`）：模型调用、设置、会话、OneBot 接口 |
| 插件外壳 | `plugins/<名字>/` | AstrBot 插件，只注册钩子和工具，逻辑转给 `kaju_core/<块>/mind.py` |

- **身份表**（`kaju_data/self/people/people.json`）：一个人的 QQ、B站 UID、抖音 sec_uid 认成同一个人，主人是谁也以它为准。B站或抖音私信她的人认到某个 QQ 号上，就并进那个人的 QQ 私聊。管理：QQ 里 `/佳树认人`，或 `botctl people`。
- **各部分互相找**：起来时 `parts.register(短名, self)`，`body.find(属性)` 先查登记表，再查 AstrBot 插件表（memorix、meme_manager 等第三方插件）。
- **部署**：`botctl deploy kaju_core` 把 `kaju_core`、`kaju_platforms`、`kaju_astr` 部署到 AstrBot 旁边并写好 `.pth`。加 `--reload` 时只重载用到改动部分的插件；改了 `kaju_core/__init__.py`、`paths.py`、`parts.py` 或 `kaju_astr` 需要重启 AstrBot。

## 数据目录

数据根目录由环境变量 `KAJU_DATA` 指定，默认在部署时写进 `kaju_core/_root.py`。

| 目录 | 内容 | 处理 |
|---|---|---|
| `self/<部分>/` | 人格正本、心情、好感、记忆、知识本、日记、称呼簿、表情包、memorix 长期记忆 | 需要备份：`botctl backup-self` |
| `accounts/` | 模型 API key（`gemini_keys.json`、`text_models.json`、`model_router.json`、`model_slots.json`）、B站和抖音登录 | 不能外传 |
| `cache/` | 下载的视频、截帧、浏览器缓存、模型成绩 | 随时可清：`botctl clean-cache` |

人格正本在 `self/persona/`（`persona.json` + 人设正文 `persona.txt`，回复器读的角色说明 `character.md`），AstrBot 数据库里的是副本：`tools/persona.py export`（AstrBot → 正本）/ `sync`（正本 → AstrBot）。

## 模型分工

| 用途 | 模型 | 配置 |
|---|---|---|
| 大脑（理解、规划、调工具） | Gemini 系列，由挑模型模块按实时成绩排序 | AstrBot 主模型 + 后备，`accounts/model_router.json` |
| 回复器（用她的口吻写出来） | Claude Sonnet 系列 | `accounts/text_models.json`，`rewrite.replyer_models` |
| 发送前核对 | Gemini Flash，带后备 | `rewrite.guard_provider_id` |
| 看图、动图、视频，听音频 | Gemini（原生接口） | `accounts/gemini_keys.json`，`model_router.json` 的 `tasks` |
| 记忆和知识的向量检索 | 本地 bge-m3（Ollama） | `local_vision/runtime.ps1` 启动，端口 11435 |
| 语音转文字 | 本地 SenseVoice（sherpa-onnx） | `stt.*` |
| 网页搜索、模型全挂时报信 | DeepSeek | AstrBot `websearch_provider`、`gemini_down_provider_id` |

**挑模型**（kaju_basics `router.py`，`kaju_core/senses/health.py`）：给 AstrBot 每个提供方的请求包一层，记下成败和耗时，存进 `cache/model_health.json`。每条消息按成绩现排候选；连续失败的先冷却，后台定时探测；私聊和提问用高思考档。带图的消息只让能看图的模型打头。`model_router.enable = false` 时按 AstrBot 配置的顺序。

## 说话流程（kaju_style）

1. **大脑**（`kaju_core/voice/brain.py`）：主模型不模仿她的语气，只想清楚这一轮怎么回，输出 JSON 指导，包括局面、要接住的、要表达的、对方需要什么、情绪、回不回、答应做的事。群聊中大脑判断不用回时这句不说（`planner_skip = group`）。大脑回的不是能用的 JSON（比如直接用她的口吻写了回复）时，拿同一份材料再问它一遍、叮嘱只输出 JSON（`rethink_timeout`）；还不行，私聊让回复器照日程说一句"这会儿在忙，等下再好好回"，群里不说。
2. **回复器**（`replyer.py`）：看她的角色说明、最近的聊天（标出哪句是她自己说的、在回谁、谁 @ 了她、图里是什么）、心情底色、大脑的指导，再加上按场合用 bge-m3 从例子库（`self/kaju_style/replyer_bank.json`）挑出的几句她以前说过的话，写成她会发的消息。
3. **核对**：拿大脑的指导和聊天对照，拦住编造的事实、叫错人、改了意思、漏了要紧的回答。被拦下就拿同一份指导重写（`rewrite.retry`）。几遍都不过时（`guard_fail = busy`）先只改被拦的那一处；还不行就说一句"这会儿在忙，等下再好好回"，这句话是照当前日程写出来的。
4. **发出前**：按聊天节奏分成几条（`rhythm`）；回复写好时对方又发了新消息，就并到新消息里一起回（kaju_basics `burst.late_merge`）。
5. **群里 @ 人**（1.31.0）：有人让她叫谁、问谁、转告谁时，大脑在 JSON 里写 `"@": ["兄长大人"]`（最多两个人）；`mind._note_at` 用这个群最近的聊天记录把名字对到 QQ 号（说过话的、被别人 @ 过的；"兄长大人"对到身份表里的兄长、他也得在这个群的记录里出现过），对不上或对上好几个人就不 @，话照发。外壳 `add_at`（最后一个发前钩子）把 @ 加在这条开头（引用之后），分段发时只挂在第一段。回复器知道这条会 @ 谁；kaju_life 把这条记成 `@名字(QQ) …`。开关 `rewrite.at`（默认开）。私聊不 @。被骚扰找兄长（kaju_heart `ask_brother_for_help`）在群里也走这条路：工具私聊告诉兄长后，放一个 `brain.AT_ADD_KEY`，她回对方的这条开头一定 @ 兄长（兄长在不在群里由工具用 QQ 查过，不再看聊天记录）；以前那种回完再另发一条 @ 已经删了。

只发回复器写的话（`writer_only`）：没写成就不说，不会把大脑的指导或报错原样发出去。主模型连后备都没答上来时，AstrBot 的报错不发，由 DeepSeek 写一两句通过 QQ 和抖音私信告诉主人（`gemini_down_notify_minutes` 内只报一次）。

插件让她主动说话时也走同一套：刷到视频想分享、补上答应过的事、QQ 空间说说（`polish`），先把别的模型起的草稿整理成和大脑一样格式的指导（`brain.FROM_DRAFT`），再交给回复器写、核对；插件只给几条要点时（看视频前先说的那句，`say_from_card`），要点直接拼成指导交给回复器。

其他提示：被纠正时先认同（`rebuttal`）、聊作品说具体（`concrete`）、先回应别当解说员（`respond`）、问之前先听懂（`asks`）、深夜催睡限频（`bedtime`）。每次回复的输入、指导、输出和核对结论记在 `self/kaju_style/rewrites/日期.jsonl`（`records.py`）。

## 插件

### kaju_basics 佳树基础

- **唤醒**：账号白名单、叫昵称、@、戳一戳（带上对方最近说的话，`poke.py`）。
- **消息管道**：私聊连发合并（`burst.*`，几秒内连发的几条并成一轮）、群聊记录按到达顺序、离得远就引用、长时间以前的群聊历史不再带（`stale.py`）、稳定前缀（把会变的提示挪到末尾，提高缓存命中）、请求时限和重发（`llm_deadline.*`）、发送前去掉重复句和多余标签、QQ 聊天中隐藏不该用的工具（`chat_tools.hide`，支持通配符）。
- **感官**（实现在 `kaju_core/senses/`）：
  - 图片、动图：先交给 Gemini 看（`omni.look`）；动图按时间取样拼成一张再看（`animation.py`）。她领会图的意思直接回应，被问"这是什么"才描述。
  - 视频：交给 Gemini 连画面带声音一起看，写下她看的时候的感受、印象最深的几个时刻和事实备忘；超长视频分段看（`omni.feel_long`）；问到某个时间点时回去截大图补看（`relook.py`）。看完的感受在写回复之前就影响心情。
  - 音乐：PyAV 转码后用 soundcheck 引擎测量（`music.py` + `soundcheck/`），再写成听感；人声用 SenseVoice 转写。
  - 文件：txt、md、字幕、代码、网页、docx、PDF、epub（`docs.py`）。长篇小说交给 kaju_learn 按人的速度一段段读。
  - 语音：本地 SenseVoice，用到时才加载，闲置后释放（`stt.idle_minutes`）。
- **B站**：认链接和分享卡片，读页面信息，下载最低画质看完；提到"弹幕"时附上挑过的弹幕，提到"评论区"时多翻几条高赞评论和楼中楼（`media.bili*`）。小号扫码登录、自动续期（`/佳树B站登录`）。
- **抖音**：用本机 Chrome 像人一样打开作品页，读页面自己收到的作品信息和评论，下载最低码率视频；不签名、不伪装，遇到人机验证就老实说没看成。小号登录后由常驻无头浏览器保持登录（`dykeeper.py`，`/佳树抖音登录`）。
- **自己刷视频**（`kaju_platforms/shared/browsing.py`）：主人说"去刷会儿B站/抖音"时调用 `browse_bilibili` / `browse_douyin`（只认主人）。她按自己的喜好挑几个看完，感受交给 kaju_heart，内容交给 kaju_learn；刷完回到叫她的地方说一声，特别想说的会主动私聊。只看，不点赞、不评论、不关注。
- **抓网页碰到视频链接**时改走看视频流程（`linkfetch.py`）。
- **Ollama 看门狗**：每分钟检查本地 Ollama，没开就用 `local_vision/runtime.ps1` 拉起。

### kaju_heart 心情与好感

心情（全局一份，开心、精神、委屈紧张、想黏人四维，各有基线，按半衰期回落，精神跟作息走）；好感（每人一份，0~100）；关系的几个侧面；心事和余韵；心里记下的想法（写进 memorix，以【佳树心里】开头）；喜好在相处中自己长出来；自己刷到的视频带来的感受（`feel_browsed`）；看视频、读书时的感受随内容推动心情（`feel_moment`）。最依赖主人：被骚扰时找他帮忙（`ask_brother_for_help`：私聊告诉他；在群里她回对方的那条开头 @ 他，走 kaju_style 的群里 @ 人）。命令 `/好感度`、`/佳树心情`。

### memory_weight 记忆轻重

memorix 对所有记忆一视同仁，这里补上轻重：郑重的话、常用的事记得牢，琐碎又没用过的闲聊慢慢褪色（遗忘曲线）。铭记重要的话；用上过的记忆更牢；触景生情时想起旧事；珍藏别人分享的文件（`recall_shared_file`）；工作记忆记下刚才聊天的要点；对方还没结果的事列进【还没结果的事】；每天给常说话的人写一份综合印象，替换 memorix 的流水账画像（拿不准的玩笑单独放）。命令 `/记忆轻重`、`/佳树备忘`。

### kaju_learn 学到的东西

- **从哪儿学**：聊天（私聊、群聊）、看过的视频和书、听过的歌、网页搜索。一段聊天安静下来后整段交给模型抽取。
- **怎么记**（`book.py`）：一样东西一条，记大类、是什么、知道的点、她的看法、和别的东西的关系；越常碰到、越常用上越熟，不碰慢慢记不清。纠正旧知识必须指出是谁纠正的。不记群友的私事，也不把"她就是这个角色"当知识。
- **睡前消化**：合并、去重、理顺矛盾，核对旧事实（两道关，宁可漏也不乱改）。
- **自己去弄明白**：想弄明白的事拿去 B站搜，或者每隔几小时上网查一件。
- **复盘**：每晚复盘前一天，总结教训（证据必须是别人的话或程序记录），每轮挑两三条给大脑；顺带学"关于自己"的能力和经历；按群学这个群的叫法。命令 `/佳树教训`。
- **边读边想**（`reading.py` + `reader.py`）：长篇按章节切段，后台按人的速度一段段读，每段都有想法和情绪；读到特别想说的地方主动告诉主人；进度如实汇报，读不成会说。长视频也一段段看。
- 聊天时，提到的或意思相近的条目以【你知道的】给她（`recall_knowledge`）。命令 `/佳树学到的`。

### kaju_life 佳树的生活

每日小日程（只在被问起时给她看，讲过的标"说过了"），日记、周记、月记（`read_diary` / `search_diary`，`/佳树日程`、`/佳树日记`）。日记里"还记着的事"只记约定、答应的事、在等结果的事。**关于自己**（`selffacts.py`）：每轮按对方的话，用 bge-m3 从 `self_facts.json` 挑出相关的几条。

### address_book 称呼簿

"兄长大人"只叫主人；别人默认"群名片 + 学长/学姐"（性别查 QQ 资料）。工具 `set_address` / `clear_address`。主人优先读身份表，其次读配置 `owner_qq`，最后读环境变量 `KAJU_OWNER_QQ`。

### smart_chime_in 聪明插话

决定群聊中什么时候主动接话：基础概率、每小时上限、冷却（冷却完再看一次）；判断"接着聊"时排除对方转头在跟别人说话的情况；群里的"你"大多不是在指她；同一个人连着发只回一次；长公告和 @全体 不插话；只剩附和、复述或者不知道该说什么时不回。控制台的"群聊插话"滑块改的就是它。

### kaju_dm 佳树私信

B站和抖音上和她互关的人可以私信她聊天、发视频，按 QQ 私聊的完整流程回复（`turn.py` 把私信变成私聊事件）。她回关别人、别人每天超过额度的视频，都要主人在 QQ 上批准（`/佳树私信 批准 n`）。B站走网页私信接口，抖音走常驻浏览器里的私信页；连发合并，按消息编号去重；表情包分别改发 B站图片和抖音表情。私信里的人说自己是 QQ 上的谁时，登记一件"是不是同一个人"等主人决定（`claim_same_person`）。

### follow_through 说到做到

维护她的能力清单；答应的事没做（包括大脑指导里的"答应"）就在后台补做，按挑模型的顺序换家，超时如实说没做成。**新加的 LLM 工具必须加进 `CAPABILITY_LABELS`**，否则她会说自己做不到。

### qzone_post 发说说

每晚到点选材、写稿、核对，存为草稿，主人用 `/佳树说说 发` 批准后才发出（`nightly.*`）。点赞和评论互动目前关闭（`interact.enable = false`）。

### group_peek、meme_saver

`peek_group_chat` / `send_group_message`；`save_meme`（依赖 meme_manager）。

### 第三方插件

memorix（长期记忆）和 meme_manager（表情包）的源码不在这里，本地改动见 `patches/`，插件更新后要重新打补丁：

- `memorix-local.patch`：提取用户信息时，聊角色或聊别人的话不算用户本人的事实；向量库拒收 NaN 向量；记忆模型按 `model_slots.json` 的顺序带后备；自动带上的记忆也纳入反馈纠错。
- `meme_manager-local.patch`：各包按包均分；同义小分类合并（`category_aliases.json`）。

## 测试

`tests/` 下每个 `test_*.py` 用 AstrBot 的 venv Python 加 `-I` 运行，AstrBot 由 `tests/stubs` 代替，不需要机器人在跑，结尾打印 ALL OK。部分测试带 `--live` 参数，会调用真实模型（只打印，不发消息）。测试里的 QQ 号和昵称都是假的。
